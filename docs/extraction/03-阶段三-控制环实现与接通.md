## 2. 环境变量（禁止入库）

在仓库根目录 `.env`（已 gitignore）配置：

```bash
# ReAct 等共用
DEEPSEEK_API_KEY=sk-...

# Extraction 专用（推荐单独一把）
DEEPSEEK_EXTRACTION_API_KEY=sk-...
DEEPSEEK_EXTRACTION_TEMPERATURE=0.1
# DEEPSEEK_EXTRACTION_MODEL=deepseek-chat
```

加载逻辑：`shared/llm/client.py` → `load_llm_config(profile="extraction")`。

> **安全**：API Key 只放 `.env` / 环境变量，**不得**写入文档、代码、提交记录。若 Key 曾出现在聊天中，建议在 DeepSeek 控制台轮换。

## 3. 怎么跑

```bash
cd enterprise-anti-ai-silo-demo
source .venv/bin/activate   # 若已建 venv
# 确认 .env 已填 DEEPSEEK_EXTRACTION_API_KEY

# 工单字段抽取（Story1 Extraction 路径）
python apps/cli.py --agent-type extraction --skill ticket_fields \
  --input data/seeds/story_1_ticket_fields.json --json-out

# VoC 打标
python apps/cli.py --agent-type extraction --skill voc_entities \
  --input data/seeds/story_1_voc_entities.json --json-out

# 别名 Skill
python apps/cli.py --agent-type extraction --skill voc_tagging \
  --input data/seeds/story_1_voc_entities.json

# 只校验不写库
python apps/cli.py --agent-type extraction --skill ticket_fields \
  --input data/seeds/story_1_ticket_fields.json --no-write

# 冒烟脚本
python scripts/smoke_extraction.py
```

API 示例：

```bash
curl -s http://127.0.0.1:8000/v1/extraction/runs \
  -H 'Content-Type: application/json' \
  -d '{
    "skill_id": "ticket_fields",
    "input": {
      "text": "投诉门店未按三包政策处理电池更换，工单已超过7天未结。",
      "customer_id": "CUS-10057",
      "vin": "QS0F65B984410D7B6",
      "channel": "400"
    }
  }'
```

## 4. 代码地图

| 文件 | 职责 |
|------|------|
| `agents/extraction/skill_schema.py` | Extraction Skill 契约（含 `payload_schema`） |
| `agents/extraction/skill_loader.py` | 加载 YAML |
| `agents/extraction/prompts.py` | System / User / Retry 消息 |
| `agents/extraction/validate.py` | JSON 剥离、Schema、阻断闸门 |
| `agents/extraction/agent.py` | 控制环 + `write_ai_output` |
| `apps/skill_dispatch.py` | React / Extraction Skill 分流 |
| `apps/cli.py` | `--agent-type extraction` |
| `apps/api.py` | `POST /v1/extraction/runs` |
| `apps/catalog.py` | `F-SVC-001-EXT`、`F-VOC-002` demo_ready |

与 ReAct 的边界：

- ReAct Skill：有 `allowed_tools`，无 `payload_schema`
- Extraction Skill：有 `payload_schema`，LLM 路径**不调 tools**；校验通过后由代码调 `write_ai_output`

## 5. 成功判定

| `stop_reason` | 含义 |
|---------------|------|
| `validated` | Schema + 闸门通过（可已写 AIOutput） |
| `bad_input` | 空文本 / 超长 |
| `schema_fail` | 重试后仍不合规 |
| `llm_error` | DeepSeek 调用失败 |
| `write_fail` | 校验通过但写共享层失败 |
| `config_error` | 字典缺失等 |

Demo 验收：`ok=true` 且 `ai_output_id` 非空（未加 `--no-write` 时）。
