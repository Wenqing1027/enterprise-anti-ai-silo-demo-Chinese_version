> 版本：V2.0 · 2026-08-06

---

## 痛点

各部门各自搭 Agent、各自复制数据访问与半套控制环 → **AI 孤岛 ≈ 数据孤岛**。  
再「共用一个企业 Agent」也救不了：重复仍发生在 **环与手脚**，业务差异却被塞进人设 Prompt，无法治理。

---

## 主张（对客户怎么讲）

企业 AI 转型成品是三件套：

1. **Control Loops（平台）** — 有限的认知执行模式（本 Demo：**4**）  
2. **Tools（平台）** — 统一工具台账与批准边界（本 Demo：**3 类**）  
3. **Skills（业务部门）** — 各部门自建功能插件，挂到某环、选用已批工具  

跨部门 / 跨功能协作靠 **共享语义与 AI 产出资产**：各功能是独立 Skill，**一次运行一个**；不靠 Agent 互聊，不靠复制对方私库。

## 分期建议（咨询口径）

| 期 | 做什么 |
|----|--------|
| 先 | 平台四环骨架 + 三类工具治理 + 共享标签/`AIOutput`/能力目录 |
| 再 | 各部门批量挂 Skill；用 flows 标清串并与消费关系 |
| 后 | 加强 Plan 运行时、评测与审计；按需拆 Vision 等扩展环 |

作品集 Demo：Retrieve / Act / Extract 已可跑；Plan 以契约 + Story2 闸门语义为主（运行时可续作）。

---

## 部门内与跨部门

- **一功能一 Skill**：入口选功能即选 Skill；不在运行中把结果「递给」另一个 Agent  
- **跨功能**：后跑的 Skill 只读共享层；关系见 `docs/planning/`、`department_flows.json`（说明书，非联跑）  

---

## 反模式（当面否决）

- 一个万能 System Prompt 当「企业大脑」  
- 按部门各建一套互不相通的 Agent + DataFetcher  
- 宣称「共用 Agent」即已反孤岛  
- Multi-Agent 互聊 / Agent→Agent 管道接力当协作主路径  
- 单 Orchestrator 包办全公司流程  

---

## 一句话收束

**平台管环与工具，部门交 Skill，共享层打通产出——这才是可治理的 Anti-AI-Silo。**
